# 经济系统命令安全与性能审计

## Goal

审计 `nextbot/plugins/economy.py` 中的 4 个 `category="经济系统"` 命令，找出安全漏洞、缺陷、性能瓶颈，按严重级别整理报告（不直接修复）。

## 审计范围

| 命令 | display_name | command_key | 大致行号 |
|---|---|---|---|
| 1 | 签到 | `economy.sign` | 86–232 |
| 2 | 转账 | `economy.transfer` | 233–319 |
| 3 | 添加金币 | `economy.coins.add` | 320–389 |
| 4 | 扣除金币 | `economy.coins.remove` | 390–459 |

## 审计维度（与上一次 用户系统 审计一致）

### 安全
- 金币原子性：扣 → 加是否在同一事务里？
- 越权：扣别人钱 / 给别人钱时是否检查权限 / 调用方身份
- 输入校验：金币数量负数 / 超大值 / 非整数 / 空白
- 竞态：并发签到 / 并发转账（A→B + B→A 同时发生）
- 自我转账 / 转账给自己 是否被屏蔽
- 整数溢出（极大金币加和）

### 缺陷
- 错误处理路径完整性
- session try/finally close
- 转账中途失败的回滚
- 签到日期判定（时区、跨日边界）
- 部分成功 / 部分失败（如签到额外发奖时一致性）

### 性能
- N+1 查询
- 重复 session 开关
- 不必要的全表扫
- 单事务包含太多业务（事务过大）

## Acceptance Criteria

- [ ] 4 个命令逐一过一遍
- [ ] 每个发现按 严重级别（🔴 必修 / 🟠 应修 / 🟡 建议 / 🟢 观察）分类
- [ ] 每个问题包含：现象描述 / 影响 / 复现步骤 / 修复方案 / 严重级别
- [ ] 误报由主代理二次复查后剔除
- [ ] 所有发现写到 `research/findings.md`，主代理读取后向用户输出最终报告

## Non-goals

- 不修复任何代码（这是审计任务）
- 不审计 抢劫 / 抢劫保护（在其他 category）
- 不审计 红包系统、签到排行榜等关联但不在经济系统 category 的命令

## Definition of Done

- 输出最终报告给用户，问题已经过主代理复核
